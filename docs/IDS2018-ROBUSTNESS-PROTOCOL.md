# CSE-CIC-IDS2018 cross-version robustness protocol

Registered before examining any 15 or 16 February model outcomes. This is a qualified comparison across separately generated captures using related flow-meter versions; it does not establish operational network performance or exact feature equivalence. The 2018 publisher specifies CICFlowMeter-V3 but not the exact producing revision or configuration. Timeouts, flow termination, packet interpretation and statistics may differ from the 2017 data. Known problems in the source attack scenarios and schedule-derived labels limit the meaning of measured detection ([2018 correction investigation](https://intrusion-detection.distrinet-research.be/CNS2022/CSECICIDS2018.html)).

## Fixed data and models

Use the official 15 and 16 February 2018 processed daily CSV objects, full files, exactly as supplied in the publisher's AWS bucket; the 14 February file is development only. Record SHA-256, byte length, ETag and last modification before opening their tabular contents. These days are correlated time blocks from one experimental testbed. Do not use any scores from them to select features, thresholds, models, preprocessing, data inclusion or metrics. The selected original and corrected binary-only balanced-subsample bundles and their independently frozen validation thresholds are in `artifacts/external-evaluation-frozen-binary/`; verify their hashes/environment before use. Identity passthrough and canonical 27-feature order remain fixed.

Documentary basis for distinct capture: the publisher describes [CICIDS2017](https://www.unb.ca/cic/datasets/ids-2017.html) as recorded 3–7 July 2017, whereas its [2018 dataset schedule](https://www.unb.ca/cic/datasets/ids-2018.html) lists the reserved attacks on 15–16 February 2018. Different dates and documented environments support treating these as distinct captures, but do not independently authenticate every record or establish different behavior, tools or production-network representativeness. Feature-hash matches are reported separately from this provenance evidence.

Map the 27 source column aliases defined by `attack_traffic/inspect_ids2018.py` to the corresponding canonical feature positions, without transformations. Expected duration and interarrival units are microseconds and lengths are bytes, but this is a provisional cross-version assumption, not verified equivalence. Require exactly one of every alias and `Label`. Fail on schema ambiguity or unknown labels; do not use ports, IPs, timestamps or labels as model features. Label map: `Benign` is benign; `DoS attacks-GoldenEye`, `DoS attacks-Slowloris`, `DoS attacks-SlowHTTPTest`, and `DoS attacks-Hulk` are attack. Treat labels as supplied, not adjudicated ground truth. An unexpected label blocks scoring pending a new documented decision.

Log every exclusion by file and row ordinal: repeated header rows and malformed-width rows are excluded with reasons; numeric values must all be finite and duration nonnegative. No imputation or per-label sampling. Retain legitimate repeated feature vectors. Check exact source identity and documented capture provenance for overlap; count feature-vector matches against frozen groups and report them separately because equal values do not prove a common flow. If provenance reveals actual shared capture, halt rather than silently discard. The existing general external-contract checker rejects any match and therefore is not an appropriate final scorer without an explicitly reviewed change to this policy.

Before scoring, independently verify input file hashes, mapping, class support and model bundle metadata. Calculate frozen-threshold TP/FP/TN/FN, recall, false-positive rate and precision separately for each day and pooled, for each frozen model. Include per-source-label support and detections, zero-score counts, total exclusions and feature-collision counts. Null metrics for zero denominators. Disclose that flow-level uncertainty assumes independence and temporal dependence is not modeled; two days are insufficient for reliable block confidence intervals. Report every predetermined result, including weak or failed results. Do not promote the models or change thresholds based on this evaluation; future changes require a new independent assessment.
