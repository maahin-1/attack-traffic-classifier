# Experiment 009: scanning1 development probe

The `GroundTruth_Network_1.csv` development file and the fully scanned `normal_scanning6.pcap` did not overlap in time under a Unix-epoch interpretation. A later, header-only inventory of the other ZIP members found that `normal_scanning1.pcap` begins one second before the earliest timestamp in the CSV. This is a post-hoc reason to investigate, not proof of a match or independent confirmation.

Read only `normal_scanning1.pcap` fully and validate its internal ZIP CRC, format, interface and time range; inventory the supplied CSV as in the scanning6 plan. Select the first up to 50,000 valid distinct same-second TCP/UDP IPv4 event keys whose CSV timestamps fall in the PCAP range; reread the PCAP and count same-second exact directional and separately reverse-direction tuple matches. Keep raw addresses and ports out of reports. Record packet and selected-event multiplicities, unsupported packets and incomplete ranges. Use recorded timestamps directly with no fitted timezone offset. Treat matching as preliminary packet/event compatibility: it does not establish flow-level labels, duration, ground-truth correctness or network generalization.

This member and the CSV become consumed development material. The other members remain unassessed except for their previously recorded first packet headers; no independent final holdout has been reserved. Do not train, score, calibrate, select model features, or change thresholds as part of this probe. Lock any later extraction and label-alignment policies on separate development evidence before assessing a distinct holdout.
