## Evidence and interpretation

- **Original export choice:** UNB describes timestamp-based labeled flows but does not expose complete archive headers on the landing page. A [primary research study using GeneratedLabelledFlows](https://link.springer.com/article/10.1007/s44354-026-00048-9) reports retained identity/timestamp fields and distinguishes the stripped MachineLearningCSV export. This supports selecting GeneratedLabelledFlows for inspection; it does not certify our not-yet-acquired files. Fail if actual event timestamps are absent, rather than deriving them from row position.
- **Correction lineage:** the [WTMC2021 page](https://intrusion-detection.distrinet-research.be/WTMC2021/tools_datasets.html) records several regenerated uploads and explicitly links subsequent work. The chosen [CNS2022 work](https://intrusion-detection.distrinet-research.be/CNS2022/index.html) provides recreated datasets. Preserve both original and correction-paper citations in the eventual report.
- **Attempted flows:** follow the [CNS2022 guidance](https://intrusion-detection.distrinet-research.be/CNS2022/Dataset_Download.html) for the primary experiment: map attempted flows to binary benign and family benign. Preserve original attack family, raw label and attempted category as audit metadata. Do not create separate attempted model classes. `Attempted Category` and every label-derived field are forbidden features. Version the exact mapping after enumerating real labels; never guess spelling or category coding from synthetic fixtures.
- **Clock handling:** [CNS2022 tools documentation](https://intrusion-detection.distrinet-research.be/CNS2022/Tools_Documentation.html) states UTC timestamps with microsecond precision. The original export's precise timezone/format is not established by that statement. Verify original times against documented capture/attack windows; record each adapter's declared assumptions and normalize to UTC before applying shared boundaries. Do not assume the same format/timezone for both exports.
- **Duration units:** the maintainer's [BasicFlow.java](https://raw.githubusercontent.com/GintsEngelen/CICFlowMeter/master/src/main/java/cic/cs/unb/ca/jnetpcap/BasicFlow.java) computes duration as last-packet time minus first-packet time; its rate calculations divide duration by 1,000,000 to obtain seconds, and source comments explicitly identify microseconds. For the inspected corrected export, derive an audit-only end time as start plus `Flow Duration` microseconds; do not confuse it with the separately supplied `Total TCP Flow Time`. This source check establishes the documented extraction convention, not archive-to-source-commit identity.
- **Terms:** the [UNB License section](https://www.unb.ca/cic/datasets/ids-2017.html) describes research availability and requests citation of Sharafaldin, Lashkari and Ghorbani (ICISSP 2018). The reviewed CNS2022 download/tools pages and code README provide provenance/citation guidance but no explicit dataset redistribution license was verified. Public access does not establish blanket redistribution rights. Inspect archive terms after acquisition; keep archives and real data local and untracked.

## Candidate chronological design

Propose **train Monday–Tuesday (3–4 July 2017), validation Wednesday (5 July), test Thursday–Friday (6–7 July)**. This is an inventory-based starting proposal, not a frozen experiment configuration. UNB documents Monday as benign-only and attack traffic on later days; Monday-only training would violate binary fitting support. Train through Tuesday to include attack observations. These days intentionally leave later attack families unseen and require explicit unseen-family reporting. [Capture and attack schedule](https://www.unb.ca/cic/datasets/ids-2017.html)

After timezone verification, propose UTC cutoffs at the starts of 5 July and 6 July; confirm these separate the intended capture days in both variants. Before freezing them, audit all retained counts after cleaning/deduplication and require both binary classes in train and validation. If support fails, revise using inventory alone. Do not inspect test model scores when selecting boundaries. Quarantine flows spanning cutoffs using verified end timestamps or a documented duration-to-end calculation; disclose any incomplete timing evidence.

## Corrected archive: complete streaming inventory

Ran `python scripts/inspect_corrected.py` against the pinned local archive. It streamed all members without extraction, checked the exact expected member names and byte ceilings, strictly decoded UTF-8 CSVs and consumed each member to EOF so `zipfile` verified CRCs. Results are saved in `data/cns2022/inventory.json`; no raw identifiers were exported and no model scores were inspected.

Observed 2,099,976 rows and 1,152,270,765 total uncompressed bytes across five daily members; the archive contains no additional bundled license or README member. Each CSV has 91 columns, including `Timestamp`, `Flow Duration`, `Label`, `Attempted Category`, network identifiers and a row `id`. There is no explicit end-timestamp column. All starts parsed as `%Y-%m-%d %H:%M:%S.%f`; UTC interpretation follows maintainer documentation. No malformed field counts, timestamp parse failures, negative/nonfinite/nonnumeric durations or noninteger duration values were observed. This scan validates those fields only; it does not certify every numeric model feature or raw label's ground-truth correctness.

## Acquisition and adapter gates

1. **Before sizeable downloads:** present concrete assets, destinations and transfer/disk scope. Corrected transfer is advertised `328M`; original archive and extracted sizes remain unverified, so a combined size must not be invented. No PCAP download or flow regeneration is needed for the proposed CSV comparison. Resolve portal access with the user if registration is required.
2. **At acquisition:** retain exact source URL, response size where available, retrieval UTC timestamp, supplied checksum/terms references and local SHA-256. Keep variants separate and raw archives immutable. Corrected acquisition and full ZIP inspection are complete; no full extraction was needed. Review paths before any future extraction.
3. **Before declaring adapters ready:** inventory actual member names, normalized/raw headers, encoding, duplicate headers, label values, timestamp formats/timezones and duration units. Record explicit duplicate-column handling rather than allowing a CSV parser to rename ambiguous columns silently. Build per-release schema adapters from this evidence; do not create a fabricated production configuration from the demo schema.
4. **Before fitting:** establish semantic feature intersection and units; preserve attempted metadata while excluding it from inputs; derive end times only from verified timing fields; sort each CSV if required by the audit interface; run quality/split audit and reconcile every disposition by raw label and variant.
5. **Before performance claims:** benchmark the chosen subset/full profiles locally and record real resource use. Stream ingestion and a disk-backed duplicate index do not themselves establish a runtime or throughput claim.
