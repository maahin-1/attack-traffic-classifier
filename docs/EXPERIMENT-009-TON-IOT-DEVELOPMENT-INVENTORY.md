The three-page publisher README describes network packet captures and Bro/Zeek logs, and says the security events were labeled using attacker addresses and timestamps. It does not map individual `GroundTruth_Network_*.csv` files to individual PCAPs, nor does it establish that each event equals a complete bidirectional flow. It states academic-research and commercial-use conditions; check the authoritative publisher source and applicable terms before use or distribution. Keep endpoint information out of model inputs and published reports.

The first 50,000 CSV data records were inspected as a bounded convenience sample in file order, not a random or full-file inventory. All 50,000 had seven columns: `ts`, `src_ip`, `src_port`, `dst_ip`, `dst_port`, `proto`, `type`. In that prefix, `type` was always `scanning`, and `proto` was `tcp` for 48,250 rows and `udp` for 1,750; none of the seven fields was blank. Timestamps in the inspected prefix were integer-like Unix-epoch values, with observed minimum 1556021410 and maximum 1556023697 (interpreting them as UTC gives 2019-04-23). This is an interpretation of the numeric format, not independently verified capture timezone, flow start, event duration or publisher labeling precision. The sample cannot establish the remaining file's coverage or class distribution.

The accessible official listing has a `Raw_datasets/network_data/Network_dataset_pcaps/normal_attack_pcaps/normal_scanning/` folder. It lists `normal_scanning6.pcap` as 458 MB and other scanning captures from 589 MB to 1.13 GB. This filename does **not** prove it aligns with the supplied CSV, identify a separate session, or ensure benign/attack label coverage. Verify local SHA-256 and compare packet-clock ranges, protocol and tuple alignment without assuming the match. No PCAP was downloaded during this inventory.
